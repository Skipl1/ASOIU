# Инструкция для Claude: установить и запустить АС ГРСН на этом компьютере

> **Как использовать (для человека).** Откройте Claude Code в пустой папке, куда хотите положить проект
> (например, `Документы\projects`), и напишите: **«Прочитай файл SETUP_FOR_CLAUDE.md и выполни инструкцию»**.
> Файл можно скопировать на ноутбук любым способом (флешка, почта, мессенджер) или вставить его текст в чат.
> В конце Claude скажет, какой адрес открыть в браузере.

---

## Цель

Склонировать репозиторий, установить и запустить систему **АС ГРСН** (генерация рецептов спортивного питания: React + FastAPI + PostgreSQL + Nginx, всё в Docker) так, чтобы пользователю осталось **только открыть сайт в браузере**.

- Репозиторий: `https://github.com/Skipl1/ASOIU.git`
- Ветка: **`2.0mb_norm`**
- Папка проекта внутри репозитория: **`Optimization-Methods/grsn_app`**
- Всё нужное для запуска уже в репозитории: Dockerfile, `docker-compose.yml`, скрипты `scripts/setup.ps1` и `scripts/setup.sh`.

## Правила

1. **Не меняй исходный код** проекта и не коммить/не пушь ничего. Задача только установить и запустить.
2. **Не выводи в чат и не логируй** содержимое `.env` и ключ GigaChat. Файл `.env` в git не попадает, так и должно быть.
3. **Никогда не запускай `docker compose down -v`** и `--reset` без прямой просьбы пользователя: это удаляет все данные.
4. Команды `docker compose ...` выполняй **только из папки `grsn_app`** (иначе ошибка `no configuration file provided: not found`).
5. Если для шага нужны права администратора, установка программ, перезагрузка или вход в аккаунт, **остановись и скажи пользователю**, что именно сделать. Не пытайся обходить.
6. Первая сборка занимает **5–15 минут** (скачиваются образы и зависимости). Запускай её в фоне и следи за выводом, а не ставь короткий таймаут.

## Шаг 0. Проверка окружения

Определи ОС и проверь инструменты:

```
git --version
docker --version
docker compose version
docker info
```

| Результат | Что делать |
|---|---|
| `git` не найден | Попроси установить Git: Windows `winget install -e --id Git.Git`, macOS `xcode-select --install`, Linux `sudo apt install git`. Проси подтверждение пользователя перед установкой. |
| `docker` не найден | Нужен **Docker Desktop** (Windows/macOS: https://www.docker.com/products/docker-desktop/ , Windows также `winget install -e --id Docker.DockerDesktop`) или Docker Engine + compose-плагин (Linux). На Windows требуется включённый WSL 2 (установщик предложит). **После установки обычно нужна перезагрузка**: сообщи об этом пользователю и дождись его возвращения. |
| `docker info` пишет, что демон не запущен | Windows/macOS: запусти Docker Desktop и подожди, пока в нём появится «Engine running» (до 2–4 минут). Скрипт установки умеет делать это сам. |

Дальше шаги выполняются, только когда `docker info` отрабатывает без ошибок.

## Шаг 1. Клонирование

В текущей папке (в нужное место пользователя):

```
git clone --branch 2.0mb_norm --single-branch --depth 1 https://github.com/Skipl1/ASOIU.git
cd ASOIU/Optimization-Methods/grsn_app
```

- Если Git просит логин и пароль (репозиторий приватный), **попроси пользователя авторизоваться** (`gh auth login` или токен GitHub) и повтори. Не придумывай учётные данные.
- Если папка `ASOIU` уже существует, выполни в ней `git pull` вместо клонирования.
- Проверь: `ls` показывает `docker-compose.yml`, `.env.example`, папки `backend`, `frontend`, `scripts`.

## Шаг 2. Ключ GigaChat (необязательно)

Спроси пользователя одним коротким вопросом: **«Есть ли у вас ключ авторизации GigaChat (Authorization Key с developers.sber.ru)?»**

- **Есть:** попроси вставить ключ и передай его скрипту параметром (шаг 3). Ключ не повторяй в ответах.
- **Нет / не сейчас:** продолжай без ключа. Система полностью работает, но рецепты составляет встроенный локальный генератор, а на экране генерации будет предупреждение. Ключ можно добавить позже (раздел «Дополнительно»).

## Шаг 3. Установка и запуск одной командой

Находясь в папке `grsn_app`:

**Windows (PowerShell или Git Bash):**
```
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\setup.ps1
```
с ключом GigaChat:
```
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\setup.ps1 -GigaChatKey "<ключ>"
```

**Linux / macOS:**
```
bash scripts/setup.sh
bash scripts/setup.sh --gigachat-key "<ключ>"
```

Скрипт сам:
1. проверяет Docker и при необходимости запускает Docker Desktop;
2. создаёт `.env`: случайные пароль БД и секрет JWT, **свободные порты** (по умолчанию сайт 8080, HTTPS 8443, БД 5432; если заняты, подбирает ближайшие);
3. выполняет `docker compose up -d --build` (миграции БД и наполнение справочников происходят при старте backend автоматически);
4. ждёт готовности (`/api/v1/health` → 200), проверяет вход демо-пользователя;
5. печатает адрес сайта и открывает браузер.

Запусти команду **в фоне** (длительная) и следи за выводом до строки **«АС ГРСН запущена: http://localhost:…»**.
Если скрипт завершился ошибкой, прочитай её текст: он содержит причину. См. «Если что-то не так».

## Шаг 4. Проверка (обязательно сделай сам)

Порт сайта: значение `HTTP_PORT` в `.env` (по умолчанию 8080). Ниже подставь его.

```
docker compose ps
curl -s http://localhost:8080/api/v1/health
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/
curl -s -o /dev/null -w "%{http_code}\n" -X POST http://localhost:8080/api/v1/auth/login -H "Content-Type: application/json" -d "{\"email\":\"demo@grsn.local\",\"password\":\"Demo12345\"}"
```

Ожидается: четыре сервиса `db`, `backend`, `frontend`, `backup` в состоянии `running` (у `db` и `backend` ещё `healthy`); health отвечает `{"status":"ok",...}`; главная страница и вход демо-пользователя возвращают `200`.

(В PowerShell вместо `curl` используй `Invoke-WebRequest -UseBasicParsing <url>` или `curl.exe`.)

Если что-то не 200, прочитай `docker compose logs --tail 60 backend` и действуй по разделу «Если что-то не так».

## Шаг 4а. Заполни учётную запись администратора (для показа)

Чтобы в аккаунте администратора были данные за месяц (профиль, замеры веса, около 120 рецептов), выполни в папке `grsn_app` (около 20 секунд, безопасно повторять):

```
# Windows (PowerShell)
powershell -ExecutionPolicy Bypass -File scripts\fill_admin.ps1
# Linux / macOS / Git Bash
bash scripts/fill_admin.sh
```

Ожидается строка «Учётная запись администратора заполнена историей за 30 дн.» и код возврата 0. Если система не запущена, скрипт скажет об этом: сначала выполни шаги 3–4.

## Шаг 5. Сообщи пользователю

Напиши коротко (без технических подробностей):

> Система запущена. Откройте в браузере **http://localhost:ПОРТ**.
> Для демонстрации: **demo@grsn.local / Demo12345** (рецепты и история за две недели уже есть).
> Администратор: **admin@grsn.local / Admin12345** (в аккаунте уже есть история за месяц).
> *(Если ключа GigaChat не было:)* Рецепты сейчас составляет встроенный генератор; ключ GigaChat можно добавить в любой момент.
> Остановить: `docker compose stop`; запустить снова: `docker compose up -d` (в папке `grsn_app`).

Укажи реальный порт и полный путь к папке `grsn_app`.

## Если что-то не так

| Симптом | Причина и решение |
|---|---|
| `no configuration file provided: not found` | Команда запущена не в папке `grsn_app`. Выполни `cd` в неё. |
| `Docker не найден` / `daemon is not running` | Установи или запусти Docker Desktop (шаг 0). На Windows проверь, что включён WSL 2 и виртуализация в BIOS. |
| `port is already allocated` / `address already in use` | Порт занят. Если `.env` уже создан, измени `HTTP_PORT` / `HTTPS_PORT` / `DB_PORT` в `.env` на свободные и выполни `docker compose up -d`. При первом запуске скрипт подбирает свободные порты сам. |
| Сборка падает с ошибкой сети (`failed to resolve`, `timeout`, `TLS`) | Нет интернета или он нестабилен, либо блокируют Docker Hub / npm / PyPI. Проверь соединение и повтори `bash scripts/setup.sh` (уже скачанное кэшируется). |
| `no space left on device` | Мало места: `docker system prune -f` (удалит только неиспользуемое), освободи диск, повтори. |
| `backend` в состоянии `unhealthy` / `Restarting` | `docker compose logs --tail 80 backend`. Чаще всего БД ещё стартует (подожди минуту) или некорректный `.env` (удали его и запусти скрипт заново, **если данных ещё нет**). |
| `exec ./docker-entrypoint.sh: no such file or directory` | Файл сохранён с переводами строк CRLF. В репозитории это исправлено правилами `.gitattributes`; если клон делался с другими настройками, выполни `git config core.autocrlf false`, удали папку клона, склонируй заново. |
| В браузере «сайт не открывается», но контейнеры `running` | Подожди 30–60 секунд после старта; проверь порт в `.env`; попробуй `http://127.0.0.1:ПОРТ`. |
| На экране генерации: «Модель генерации недоступна … 401 credentials doesn't match» | Ключ GigaChat неверный или перевыпущен. Система продолжает работать на локальном генераторе. Получи новый ключ на developers.sber.ru и обнови (раздел ниже). |
| `HTTPS`: предупреждение браузера | Сертификат самоподписанный: «Дополнительно» → «Перейти». По умолчанию HTTPS выключен, сайт работает по HTTP. |

## Дополнительно

- **Добавить или сменить ключ GigaChat позже:** `scripts/setup.ps1 -GigaChatKey "<ключ>"` (или `bash scripts/setup.sh --gigachat-key "<ключ>"`). Скрипт запишет ключ в `.env` и пересоберёт контейнеры; данные сохранятся.
- **Остановить / запустить:** `docker compose stop` / `docker compose up -d`.
- **Обновить до новой версии кода:** `git pull`, затем `docker compose up -d --build`.
- **Обновить даты демо-данных** (если демо-пользователь «состарился»): `docker compose exec backend python -m app.seed --refresh-demo`.
- **Посмотреть базу данных:** подключение `localhost`, порт `DB_PORT` из `.env`, база `grsn`, пользователь `grsn`, пароль в `.env` (строка `POSTGRES_PASSWORD`). Не показывай пароль в чате без просьбы пользователя.
- **Полный сброс** (удалит все данные!): только по прямой просьбе пользователя, `scripts/setup.ps1 -Reset`.
- **Документация проекта:** `README.md` в папке `grsn_app` (архитектура, отклонения от ТП, тесты, структура).
